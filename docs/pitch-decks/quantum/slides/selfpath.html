This is the path we run whether or not we raise. The round on the next slide buys the hosted planner, the published benchmarks and a sales team up front; this path buys them one paying vendor at a time. Detail — Now: the library stays public domain and the four-drone demo is the offer. The founder's consulting pays the company's running costs, so no customer is needed to stay alive. — First vendor: a fixed-scope integration at about £150k over twelve weeks, delivered by the founder with engineers from the network, .NET engineers from Ukraine among them, on contract for the project. It pays for itself and for the benchmark it produces. — Two licences: two vendors shipping the planner inside their product on supported builds at about £40k a year each; the first engineer is hired when that recurring revenue and the next project are signed. — Two vendors commit: the hosted Swarm Planning API is built only when two vendors agree to route their customers' planning through it, so it launches with users rather than hoping for them. What changes against the funded plan — No quantum-hardware budget: benchmarks run on cloud credits or inside a paid project. No drone flight lab: demonstrations use the Crazyflie kit and ArduPilot's own simulator, where all four fleet examples already fly. No hires ahead of revenue. Common questions — "Why raise at all, then?" To publish the benchmarks and build the hosted planner while the market is still forming, rather than when two vendors happen to ask. The company does not depend on it.
