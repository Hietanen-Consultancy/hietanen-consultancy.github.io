Each column is an alternative the buyer already knows, and each row is something the buyer's own team can check. Detail — Python: Unsloth, Axolotl and the HuggingFace stack are excellent, and they match Fuuga on every row but one. For a .NET estate they are a second toolchain, owned by a specialist team the buyer does not have and would need approval to hire. — .NET libraries: Semantic Kernel, LLamaSharp and ONNX Runtime GenAI call models that somebody else made. ML.NET trains classical models and fine-tunes small text classifiers. TorchSharp is the tensor library Fuuga itself is built on. — Microsoft's path: the route Microsoft offers .NET shops today is Copilot and Azure OpenAI, running OpenAI and Anthropic models in Microsoft's cloud, rented per request. It is the default most of our buyers already have, and the reason they cannot train on their own outcomes, keep the data in their network, or keep the model if the price changes. Fuuga implements Microsoft.Extensions.AI, so it sits alongside that path rather than against it. — Typed-output startups such as Jev validate the decision-engine category and raised real money for it. Each is a hosted service that keeps the weights, which is what the second and fifth rows measure. — Serving: Fuuga serves the OpenAI- and Anthropic-compatible APIs together by default; the Python stack serves OpenAI's through a separate tool. Common questions — "What does a buyer get that a hosted API does not?" The records stay inside the network, the cost is fixed on hardware already owned rather than billed per request, and the model cannot be changed or retired by a vendor. A lender retraining a credit-decision engine each month on its own outcomes can do none of that on a rented model. — "And that a Python stack does not?" One toolchain and one team. The engineers who run the core systems also retrain, measure and serve the model, with provenance recorded by default rather than assembled. — "Could a .NET team do this with ML.NET or TorchSharp?" They could start from TorchSharp, as Fuuga did. The work is everything above the tensor library: importing open models, fine-tuning, the typed judge, compression, export and serving, all under test.
